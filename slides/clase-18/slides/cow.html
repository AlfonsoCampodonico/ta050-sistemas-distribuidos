TA050 · Clase 18 · Cómo se sirve un modelo · Kwon et al., §4.4 y §6.3 · go run ./cmd/sim cow

Tiempo: 0:58–1:02 (4 min). Idea clave: con una tabla de por medio, varias secuencias pueden compartir bloques físicos, y se copia recién cuando alguna escribe. Decir: cuando se piden varias respuestas para el mismo prompt (muestreo paralelo) o se hace beam search, todas las secuencias empiezan con el mismo prompt. vLLM no lo copia: las tablas de bloques de todas apuntan a los mismos bloques físicos, y cada bloque físico lleva un contador de referencias. Cuando una secuencia quiere escribir en un bloque compartido, el único caso es el último bloque del prompt si quedó a medio llenar, se le asigna un bloque nuevo, se copian los datos y se baja el contador del original. Es exactamente el fork() de Unix con copy-on-write. Números del repositorio (go run ./cmd/sim cow): 4 muestras de un prompt de 500 tokens con 100 tokens de salida cada una: 152 bloques sin compartir, 59 compartiendo, con 3 bloques copiados. Del paper (§6.3): ahorros de 6,1% a 9,8% con muestreo paralelo en Alpaca y de 37,6% a 55,2% con beam search; en ShareGPT, de 16,2% a 30,5% y de 44,3% a 66,3%. Preguntar a la clase: ¿por qué se copian 3 bloques y no 4? Porque cuando las otras tres ya copiaron, la cuarta queda sola con el original: su contador vale 1 y puede escribir.
