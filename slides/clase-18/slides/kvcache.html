El KV cache

Cada token deja una key y un value en cada capa

La atención compara cada token nuevo con todos los anteriores. Para eso necesita de cada uno su key y su value.

Se calculan una vez y se guardan: es el estado de cada secuencia en curso, y crece con cada token.

Bytes por token

2 × capas × cabezas KV × dimensión × bytes

El 2 es una key y un value.

TA050 · Clase 18 · Cómo se sirve un modelo · Kwon et al., §2 y §3

8

Tiempo: 0:19–0:23 (4 min). Idea clave: el KV cache es el estado de cada secuencia: las keys y values de todos sus tokens en todas las capas. Se guarda para no recalcularlo en cada paso. Decir: en cada capa, la atención compara el token actual (su query) con las keys de todos los anteriores y mezcla sus values. Si no se guardaran, en cada paso habría que recalcular las keys y values de todo el prompt y de todo lo generado: rehacer el prefill por cada token. En lugar de eso se calculan una vez, en el prefill para el prompt y en cada paso para el token nuevo, y se guardan. La fórmula: 2 (key y value) por capas por cabezas KV por dimensión de cada cabeza por bytes de cada número. Remarcar: el KV cache crece un token a la vez mientras la secuencia se genera, y nadie sabe de antemano hasta dónde va a crecer. Eso va a ser el problema.
