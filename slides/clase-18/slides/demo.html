El mismo motor corre en tiempo virtual (sim) y en tiempo real (servidor). Go 1.24, sin dependencias.

servir-tokens · go test ./...

Tiempo: 1:24–1:27 (3 min). Idea clave: todo lo de la clase se puede reproducir y modificar con el repositorio. Decir: el modelo no existe: cada iteración cuesta un tiempo que sale de un modelo de costo, 20 ms de leer los pesos más un poco por secuencia y por token de prefill. Todo lo demás es lo que hace un servidor real: admisión por orden de llegada, batching continuo, tabla de bloques, copy-on-write, desalojo con recomputación y streaming con cancelación. El mismo motor se usa en tiempo virtual en cmd/sim, para las tablas, y en tiempo real detrás de HTTP en cmd/servidor, para la demo con curl. El README tiene cinco ejercicios: chunked prefill (Sarathi-Serve), swapping, prefix caching, rate limiting por tokens y el estudio del tamaño de bloque. Los tests verifican lo que dijimos: menos de un bloque de desperdicio por secuencia, que copy-on-write copia sólo el bloque compartido, que con reserva contigua la utilización queda por debajo del 40%, que el batching continuo le gana al estático, y que al desconectarse el cliente se libera el KV cache.
